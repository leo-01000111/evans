Known bugs

Each is on the roadmap, with what fixing it involves.

  • A PID block with Limit output ticked can stall a run. Once its output reaches the limit, the solver's step shrinks towards zero and the run stops making progress. Until it is fixed, leave Limit output off and put a Saturation block after the PID, or build the PI from a Gain and an Integrator with its own limits, as the PID with a saturating actuator example does.
  • A Unit Delay fed by a continuous signal behaves as a zero-order hold. Over each sample period it shows the sample just taken, where Simulink shows the one before. Fed by another discrete block it delays correctly. A Memory block gives the previous sample from either kind of signal.
  • A fixed-step run (ode1 to ode5) does not log its last instant. The final sample is one output step before the stop time.
  • numel("hello") is 5, not 1. Text in double quotes is a character array in Evans, because string arrays are not there yet.
  • Growing a cell, struct or array one element at a time is slow. c{end+1} = k in a loop of 10,000 takes a few seconds. Preallocate (c = cell(1, n)) where you can.

Not supported yet

These stop with an error that names them rather than giving a wrong answer. The MATLAB compatibility page has the full list.

  • Language: eval, classdef, nested functions, N-D arrays (zeros(2,2,2)), integer types, string arrays and containers.Map.
  • Data: Excel files (.xlsx), and .mat files saved as version 7.3.
  • Plotting: 3-D plots, images, and annotations typed on a later line than the plot.
  • Simulink: opening .slx or .mdl files, buses, masks and block libraries, physical (Simscape-style) modelling, and a subsystem that is both enabled and triggered.
  • Symbolic maths: symbolic functions such as syms y(t), and so dsolve.
  • Platforms: no Linux build yet, and the Windows installer is not code-signed, so SmartScreen warns the first time. See the install notes.

Report an issue

A bug, a MATLAB script that does not run, a missing command, or an idea. The more of the steps you can give, the faster it gets fixed. Leave an email if you would like a reply. You can also open an issue on GitHub.

Reports are sent by email through Formspree.
