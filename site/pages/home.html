Evans, a control-systems workbench

Classical and modern control, a block-diagram simulator and a MATLAB-shaped command window in one desktop application. It covers the part of MATLAB, Simulink and the Control System Toolbox that two control courses use: CLACO (classical, frequency domain) and DYBAC (modern, state space). Its results are tested against values worked out by hand or by an independent method.

What it looks like

Three workspaces sit on a rail down the left: Analyse for the current control system, Model for the block-diagram simulator and Console for the command window, scripts and figures. View ▸ Theme picks Day, Night or the system setting.

What's in it

Analysis
One, two or four panes with seventeen contents each: step, Bode, Nyquist, Nichols, root locus, pole-zero map, margins, Routh and more, all reading the same live model.
Command window
@@n_commands@@ MATLAB-shaped commands such as tf, feedback, margin, rlocus, lqr, c2d and pidtune, with a workspace browser and history.
MATLAB scripts
The Script tab runs .m files as written, with a debugger. The Live tab opens .mlx live scripts and exports a report.
Simulator
@@n_blocks@@ block types, subsystems, Simulink's solvers (ode45, ode23, ode15s, fixed-step ode1 to ode5 and more), scopes, and linearize() from a nonlinear diagram.
Design apps
LTI Viewer, Control System Designer (drag a pole along the root locus) and a PID Tuner whose margins are exact.

Run it from source

On Windows, macOS or Linux, with Python 3.12 or newer:

git clone https://github.com/leo-01000111/evans.git
cd evans
python -m venv .venv
.venv\Scripts\activate          # Windows; elsewhere: source .venv/bin/activate
pip install -e ".[dev]"
python app.py

python app.py --check runs a headless self-test whose exit code is the number of failures. More on running from source

Stability

From 1.0, Evans keeps these promises through every 1.x release. Until then 0.x is working towards them, and a 0.x release may still break any of it. The changelog says when.

  • Model files. A .evx file written by any 1.x opens in every later 1.x. A .fmdl file written by 0.9 or later opens in all of 1.x. A file from a newer format is refused with a message, never misread. Old files are kept as test fixtures and opened on every build.
  • The console. A script that gives MATLAB's answer keeps giving it. A change to a result is made only to match MATLAB, and the changelog lists the old and new answer. Commands in the help index stay, with their argument order, and where Evans differs from MATLAB on purpose the help page says so.
  • Settings. Settings saved by any 1.x are read by every later 1.x. One that can no longer be honoured falls back to its default; it never stops Evans starting. Autosave recovery files only survive a crash of the same version.

Patch releases (1.0.x) fix bugs and add help. Minor releases (1.x.0) add commands, blocks, panes and file-format fields. Only a major release (2.0) may break a promise above, and the changelog announces it a minor release earlier where it can.

Not promised: the wording of error messages and warnings, how plots look (colours, fonts, layout), the Python-side API (evans.*), and anything the Not in Evans help page lists.

The name

Evans is named after Walter R. Evans, who invented the root locus. It was called FauxMatlab before version 0.9; models and settings saved under that name still open.
